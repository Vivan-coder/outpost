# Outpost trailer (30 seconds, real gameplay)

The trailer is recorded from the real game with `?trailer=1`. A director script (`src/trailer/director.ts`, timeline in `src/trailer/trailer.timeline.json`) calls the game's own systems at exact times. It does not change any game rule and it does not run in normal play (without `?trailer=1` nothing changes; `npm run trailer:check` verifies that).

## Make it (one command)

```
npm run trailer          # build, record 3 takes, keep the best, compose, export
npm run trailer:check    # verify the export (duration, loudness, QR code, captions, no leaks)
```

First time only: `cd tools/trailer && npm install` (QR, PNG and Playwright helpers; separate from the game's dependencies). You also need `ffmpeg`/`ffprobe` on the PATH, Python 3 with numpy (music), and Google Chrome.

**Before the final export, put the real Netlify link in `tools/trailer/config.json`** (`url`). The end card and the QR code use it, and `trailer:check` fails until it is set.

## What happens while it records

- It opens Chrome full screen (1920x1080, GPU forced to the fast graphics card) and records the whole screen with ffmpeg (`gdigrab`, 30 fps). **Do not touch the mouse or keyboard and close other windows for about 30 seconds per take.** 3 takes take about 3 minutes in total, plus about 1 minute to compose.
- The page shows a magenta frame for 0.3 s first; the trim step finds it, so every take starts at exactly the same moment.
- Outputs go to `docs/trailer/out/` (ignored by git, never in `dist/`, never deployed):
  `outpost-trailer-1080p.mp4`, `outpost-trailer-720p.mp4`, `trailer.srt`, `outpost-trailer-thumbnail.png`, `contact-sheet.png`, `check-report.json`.

## After the game changes

1. Run `npm run trailer` again. The footage is real, so UI changes show up automatically.
2. If a shot breaks (for example a button was renamed), look at `docs/trailer/out/run.log` and the `log` lines in `out/raw/takeN.json`, then fix the matching event in `director.ts`.
3. Camera positions are in the timeline (`camera`); change them there. Cut times are on the half-beat grid of 96 BPM (0.3125 s), so the music still lines up. If you change shot times, the music (`tools/trailer/music.py`) follows the timeline automatically.

## Manual recording kit (if the automatic recording ever fails)

1. `npm run build`, then `npx vite preview --port 4173`.
2. Chrome full screen at 1920x1080 on the fast GPU (Windows Settings > Display > Graphics > Chrome > High performance). Open `http://localhost:4173/?trailer=1&autostart=1`. The magenta frame appears 4 s after load; the trailer runs for 26.25 s and stops.
3. OBS: Display Capture, 1920x1080, 30 fps, MP4 or MKV, x264 CRF 14, cursor off.
4. Trim the recording to start at the end of the magenta frame (`node tools/trailer/trim.mjs N` does this if the file is `docs/trailer/out/raw/takeN.mp4`), then `node tools/trailer/compose.mjs N`.
5. Cue sheet: see `src/trailer/trailer.timeline.json` (`shots`, `captions`). The SRT is `out/trailer.srt`.

## Notes for the submission

- Everything in the footage is the real game running; the Mission Control sliders, the hands-on solar cleaning, the crew order, the storm and the report are the game's own screens. See "What the director does" below for the few places where time is compressed.
- Real data and labels are exactly as in the game (Real NASA data, Archived NASA data (2024-05), Game). Nothing archived is shown as live.
- The music is original, generated by code (`tools/trailer/music.py`). See `CREDITS.txt`.

## What the director does (so nothing is a surprise)

- The storm cutscene ("A storm is forming") runs 3.6x faster than normal.
- The briefing skips the decision cards and goes straight to the power plan; the sliders are moved by script in steps of 5.
- The hands-on solar cleaning is driven through the game's own pointer handlers (brush tool, wipe, tap the inverter) by script, quickly.
- The game clock is jumped forward to the storm warning and to the storm impact (the real storm takes about 3 minutes to arrive), and to the end of the day for the report. The sky, siren, chart marker, dose meter and crew running to the shelter are the game's own systems reacting to that.
- Camera moves are scripted glides; there is no player input.
